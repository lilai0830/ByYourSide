# 显示协议契约（后端 ↔ 镜片 HUD / 手机 App）

> 目的：把三层（镜片 HUD、手机 App、后端）之间的载荷与消息格式钉死，作为后续所有前后端开发的单一事实来源。任何一端改动载荷前必须先改本文件。

## 1. 消费端区分
后端向两类前端分发不同载荷：
- **`lens`（镜片 HUD）**：极简。仅底部气泡（状态/推理步骤）、地图（导航）、侧方 AI 输出。无配置、无文本输入控件。
- **`phone`（手机 App）**：全量。所有 AI 输出 + 推理轨迹（O1/O2/O3 标签）+ 记忆状态 + 打扰预算 + 模式 + 配置回显 + 知识库状态。

## 2. 传输
- 传输层：**WebSocket**（`/ws`）。
- 镜片页与手机页均为后端 WS 客户端，声明 `client: "lens" | "phone"`，共享同一会话状态（mode / memory / budget / model_config / kb）。
- 后端按 `client` 类型分发对应视图载荷。

## 3. 前端 → 后端 消息类型
| type | 字段 | 说明 |
|---|---|---|
| `user_input` | `{text, image?}` | 用户输入；镜片仅语音/图像，文本输入在手机 |
| `set_mode` | `{mode: 步行\|骑行\|会议\|独处}` | 切换场景模式 |
| `config_model` | `{base_url, api_key, model_text, model_vision?}` | 配置真实模型（OpenAI 兼容） |
| `upload_kb` | `{filename, content}` | 上传知识库文档 |
| `kb_list` | — | 查询已载语料（内置 + 上传） |
| `clear_memory` / `export_memory` | — | O1 记忆管理 |
| `heartbeat` | — | 保活 |

## 4. 后端 → 前端 载荷（`hud_update`）
通用字段：`mode`, `budget`, `gap_tags: [O1|O2|O3]`, `ts`, `client`

**lens 视图**：
- `bubbles: [{kind: status|reasoning|notify, text}]` — 底部气泡
- `map: {route, arrow, eta}?` — 导航地图
- `side_output: string?` — 侧方 AI 输出
- `vibration: bool` — 震动通道（骑行）
- `badge: string?` — 角标（会议/抑制时替代大字幕）

**phone 视图**：
- `ai_output: string` — 全量 AI 文本输出
- `reasoning_trace: [{step, tag: O1|O2|O3|none, detail}]` — 推理轨迹（打 Gap 标签）
- `memory: [...]` — O1 记忆当前条目
- `budget` / `mode` / `kb_status` / `config_echo` — 状态回显
- `error?` — 错误说明

**错误处理**：API 失败时不出声、不黑屏，仅发 `error_badge: string` 提示重试（优雅降级，非脚本兜底）。

## 5. O1 / O2 / O3 在载荷中的体现
- **O1 第一视角记忆**：`memory` 字段随存取更新；`reasoning_trace` 对应步骤标 `O1`。
- **O2 分级主动与抑制**：导航默认仅 `map.arrow` + `bubbles.notify`；`suppressed: bool` 标语音被抑制；`budget` 逐次递减，耗尽自动抑制。
- **O3 带宽编排**：lens 载荷按 `mode` 选 bubbles / side_output / vibration / badge；`reasoning_trace` 标 `O3` 并注明「团队假设」。

## 6. 约定
- 镜片 HUD 只渲染 lens 视图；手机 App 只渲染 phone 视图。
- 三场景（实时翻译 / 视野导航 / 看物问答）共用同一契约，靠 `gap_tags` 区分差异化逻辑。
- LangGraph / VLM / RAG / 真实模型均经本契约输出，前端契约不变即可替换内部实现。

## 7. 模型 JSON 输出架构（system prompt schema）

> 本节约死**真实模型每轮必须输出的单一 JSON 对象**（由 system prompt 强制约束）。它是「模型提案层」：后端控制器（O1/O2/O3）在分发前对其做裁剪/降级（见 §8），最终才生成 §4 的 `hud_update`。B2 模型层与 B7 LangGraph 编排均以本 schema 为输出契约与 system prompt 来源。

### 7.1 字段表

| 字段 | 类型 | 路由 | 约束 / 语义 |
|---|---|---|---|
| `HUD_Text` | string \| null | → lens `bubbles` | 镜片主气泡文本；≤ 80 字、单行优先；`null` = 不显示。控制器按 mode 决定 bubble kind（步行/独处=notify 大字幕，会议=折叠 status，骑行=配合 vibration） |
| `HUD_Image` | string \| null | → lens `side_output` | 看物问答的识别图/标注图（url 或 base64）；非该场景恒 `null` |
| `HUD_Map` | object \| null | → lens `map` | 仅导航场景：`{route, arrow, eta}`；其余 `null` |
| `HUD_Badge` | string \| null | → lens `badge` | 会议/抑制时替代大字幕的角标；与 `HUD_Text` 二选一优先 |
| `HUD_Vibration` | bool | → lens `vibration` | 骑行导航触感通道；非骑行恒 `false` |
| `Phone_Full` | string | → phone `ai_output` | 全量 AI 文本，可长（用户打开手机看的全部内容） |
| `Reasoning_Trace` | array | → phone `reasoning_trace` | `[{step:int, tag:"O1\|O2\|O3\|none", detail:string, hypothesis:bool}]`；O3 项须 `hypothesis:true` 并注明「团队假设」 |
| `Memory_Delta` | array \| null | → O1 记忆 | `[{action:"add\|update\|forget", content:string}]`；控制器落盘后回显 `memory` |
| `Budget_Request` | object \| null | → O2 预算 | `{speak:bool, reason:string}`；**仅建议**，最终由控制器裁定（预算耗尽/高打扰场景可否决） |
| `Mode_Echo` | string \| null | → phone `mode` | 回显当前模式；实际以会话状态为准 |
| `Error` | string \| null | → `error_badge` | 模型自身感知的异常；API 失败由后端发 `error`，不在此填 |

### 7.2 system prompt 约束要点（模板见 `docs/系统提示词模板.md`）

1. **强制 JSON**：每轮仅输出一个 JSON 对象，禁止额外散文；解析失败触发后端优雅降级（非脚本兜底）。
2. **双写原则**：凡上 HUD 的内容（`HUD_Text` 等）必须与 `Phone_Full` 语义一致——镜片是手机的精简版，不是另一套回答。
3. **O3 诚实标注**：任何带宽编排/输出形态决策，若属团队假设而非已证实用户需求，在 `Reasoning_Trace` 标 `hypothesis:true`。
4. **通道守恒**：`HUD_*` 只允许在对应场景非空（导航才填 `HUD_Map`，看物才填 `HUD_Image`），避免噪声上屏。

## 8. 模型输出 → 传输载荷映射与控制器网关

> 后端编排（B7 LangGraph `orchestrate` 节点）执行：模型 JSON（提案） → 控制器网关（O1/O2/O3 确定性裁决） → §4 `hud_update`（lens / phone 双视图）。

| 模型字段 | 网关处理（O1/O2/O3） | 落点 |
|---|---|---|
| `HUD_Text` / `HUD_Badge` | O2：若预算耗尽或 mode∈{会议,骑行高风险} → `HUD_Text` 降级为 `HUD_Badge` 或丢弃；O3：决定二选一展示形式 | lens `bubbles` / `badge` |
| `HUD_Image` | O3：仅「看物问答」且 mode 允许时透传 | lens `side_output` |
| `HUD_Map` | O3：仅「视野导航」开放；其余强制 `null` | lens `map` |
| `HUD_Vibration` | O2+O3：仅骑行且预算充足时生效 | lens `vibration` |
| `Phone_Full` | 透传（手机全量，不受 O2/O3 抑制影响） | phone `ai_output` |
| `Reasoning_Trace` | 透传并追加控制器自身步骤（如 `O2 suppressed`） | phone `reasoning_trace` |
| `Memory_Delta` | O1：落盘后回显完整 `memory` 当前集 | phone `memory` |
| `Budget_Request.speak` | O2：**仅建议**；控制器据 `budget.remaining` 与 mode 最终裁定 `suppressed` | phone `budget` + lens 抑制 |
| `Mode_Echo` / `Error` | 透传 / 后端覆盖 | phone `mode` / `error_badge` |

**关键不变量**：手机永远拿到 `Phone_Full` + 完整 `Reasoning_Trace`，用户「不满足 HUD 时打开手机」即基于此；镜片只看到经 O2/O3 网关过滤后的 `HUD_*`。模型无法越权绕过控制器直接全量上屏。
